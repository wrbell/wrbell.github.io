scope

UR30 collaborative robot lacks a native extrusion axis for metal paste dispensing. This project adds a stepper-motor pump as a 7th axis — the cobot commands extrusion via RTDE, a Raspberry Pi translates register values to Klipper G-code, and an SKR Pico (RP2040) drives the stepper.

End-to-end latency budget: ~5–20 ms typical (RTDE 2–5 ms → Klipper socket <1 ms → USB serial 1–3 ms → stepper <0.1 ms).

§02 · approach path

software_stack

Three-layer bridge: URScript on the teach pendant writes extrusion commands to RTDE output registers; a Python bridge daemon on the Pi reads registers and sends Klipper G-code via Unix socket; Klipper on the SKR Pico drives a [manual_stepper] pump axis with TMC2209 + custom StallGuard firmware.

479 unit tests at 100% coverage on the bridge daemon; trade studies selected Klipper (4.70), RTDE (4.85), and SKR Pico over alternatives.

posture

  1. trade · klipper

    Klipper over Lingua Franca.

    Weighted trade study scored Klipper 4.70 vs Lingua Franca 1.95 — mature stepper stack, [manual_stepper] for a single pump axis, and a Unix-socket API the bridge daemon can call synchronously.

  2. test · 479

    Bridge before hardware.

    479 pytest cases at 100% coverage on the RTDE→Klipper bridge before integration week — stub RTDE client, fake Klippy socket, StallGuard accumulator, extrusion profiles.

  3. fw · stallguard

    StallGuard on core1.

    Custom RP2040 firmware polls TMC2209 DIAG on core1 with debounce + spinlock-protected SRAM — klippy module polls at 20 Hz for pump stall detection.
